# Как поднять Веху в Docker

Образ показывает каталог проекта (корень с `atlas.yaml`) только на просмотр. Запускать
наборы pytest из него нельзя: в образе нет окружения тестов проекта и ключа
`--allow-run`.

## Сборка и запуск

Из корня репозитория `veha`:

```text
docker build -t veha:local .
docker run --rm --read-only -p 127.0.0.1:8770:8770 \
    -v "/путь/к/проекту:/data:ro" veha:local
```

Или пример compose (корень проекта — переменная `VEHA_PROJECT`):

```text
VEHA_PROJECT=/путь/к/проекту docker compose -f compose.example.yaml up --build
```

Сборке нужна сеть — она ставит зависимости пакета из индекса. Работающий сервер в сеть
не ходит: ни телеметрии, ни загрузок при старте.

## Проверка после запуска

```text
curl -s -o /dev/null -w "%{http_code}\n" -H "Host: localhost:8770" http://127.0.0.1:8770/
curl -s -H "Host: 127.0.0.1:8770" http://127.0.0.1:8770/api/graph | head -c 200
curl -s -o /dev/null -w "%{http_code}\n" -H "Host: evil.example:8770" http://127.0.0.1:8770/api/graph
```

Ожидается `200`, начало JSON графа и `400` («недопустимый Host») — последний запрос
изображает страницу с подменой DNS. При старте в журнале контейнера (`docker logs`) —
предупреждение «слушаю 0.0.0.0:8770 — не только loopback»: внутри контейнера так и должно
быть, проброс порта на `127.0.0.1` хоста держит вебморду внутри машины.

## Что настраивается

| Что | Как |
|---|---|
| Область, если их на диске несколько | `ATLAS_SYSTEM`, `ATLAS_ENV` в окружении контейнера |
| Другой порт хоста (`127.0.0.1:9000:8770`) | `VEHA_ALLOWED_HOSTS=localhost:9000,127.0.0.1:9000` |
| Имя за своим обратным прокси | `VEHA_ALLOWED_HOSTS=veha.internal:443` — точное имя, шаблонов нет |
| Закрытый каталог проекта (Linux, `0700`) | `user: "${UID}:${GID}"` в compose |

`VEHA_ALLOWED_HOSTS` — то же, что повторяемый `--allowed-host` у `veha serve`: `имя` или
`имя:порт`, без порта — порт сервера (8770). `127.0.0.1:<порт>` и `localhost:<порт>`
разрешены всегда.

## Что сервер пишет

В режиме просмотра — ничего: ни в `/data`, ни в файловую систему контейнера. Поэтому том
монтируется `:ro`, а контейнер может быть `--read-only`. Всё, что сервер умеет писать,
включается только `--allow-run`, а его в образе нет:

| Запись | Куда | Когда |
|---|---|---|
| история прогонов `runner.history` | `<artifacts_dir>/<система>/<контур>/runs.json` | после прогона набора |
| отметки МР | `<live.snapshot_dir>/mr_checks.json` | отметка в окне «Live» |
| очистка результатов Allure | файлы `<UUID>-…` в `reports.allure` | кнопка очистки |
| результаты перезапуска кейса | `reports.allure` (пишет pytest проекта) | перезапуск кейса |

`veha export-static` пишет только в `--out` — это отдельная команда, не сервер.

## Пути и права

- Пути в `atlas.yaml` — относительные внутри корня: абсолютных путей хоста в контейнере
  нет. `veha init` пишет в `reports` только такие.
- Сервер работает под uid 10001. На Linux файлы проекта должны читаться «прочими»:
  `atlas.yaml` от `veha init` создаётся с правами `0666 & ~umask` (обычно `0644`), каталоги
  должны иметь `o+x`. На Docker Desktop (Windows, macOS) права тома не мешают.

## Чего здесь нет

Входа в вебморду: до него (этап 3 дорожной карты) порт публикуется только на loopback
хоста. Публикации образа в реестр — образ собирается из исходников. Состояние — в
[[status]].
