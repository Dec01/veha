# Решение: имя проекта и имя формата — разные вещи

Принято 2026-09-06, действует везде.

## Решение

| | Имя | Где встречается |
|---|---|---|
| Проект | **Веха** | сайт, интерфейс, документация |
| Имя пакета сервера | `veha` | код этого репозитория |
| Команда сервера | `veha` | `veha serve`; в плане — `veha update`, `veha baseline diff` |
| Агент сбора | `partest-atlas` | PyPI, отдельный пакет |
| Команда агента | `partest-atlas` | `partest-atlas wrap -- …` |
| Технические имена данных | `atlas.yaml`, каталог `atlas/` | конфигурация и артефакты в проекте с тестами |

## Почему технические имена не переименованы в `veha`

`atlas.yaml` и каталог `atlas/` — часть контракта с агентом и с уже существующими
установками. Имя проекта и имя формата данных живут в разных плоскостях, и смешивать
их дороже, чем объяснить разницу один раз.

Переименование формата означало бы миграцию у каждого, кто уже собрал артефакты, ради
косметики. Формат читает чужая программа: его владелец — `partest-atlas`, потребители —
`partest-load` и этот сервер.

## Почему команда агента не называется `atlas`

Короткое имя занято в экосистеме (MongoDB Atlas CLI). Конфликт имён команд на чужой
машине ловится дорого: он проявляется не при установке, а при запуске, у чужого
человека, на чужой машине, без доступа к нам.

Длинное `partest-atlas` — осознанная плата за отсутствие этого класса инцидентов.

## Последствия

- В интерфейсе и в документации для пользователя — «Веха».
- В коде, в путях и в конфигурации — `veha` и `atlas` по таблице выше.
- Агент называется `partest-atlas` и в имя проекта не переименовывается: он
  публикуется отдельно и живёт без сервера ([[status]]).
