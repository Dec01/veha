# Изменения «Вехи»

Журнал изменений поведения сервера. Версия не назначена (`0.0.0.dev0`): всё, что ниже, —
в разделе «Не выпущено» до первого выпуска. Изменения до заведения файла —
в `docs/wiki/log.md`.

## Не выпущено

### Статический снимок вебморды

- **`veha export-static --root <каталог> --out <каталог>`** — снимок для статического
  сайта: страница, статика, экраны и ответы API режима просмотра JSON-файлами (граф,
  карточки узлов и тестов, список тестов, вложения, логи, история раннера,
  `/api/artifacts` без абсолютного пути). Страница с `<meta name="veha-mode"
  content="static">` читает их по относительным путям и выключает с подписью «в демо
  недоступно» перезапуск кейса, раннер, опрос «Live», лог контейнера, отметки МР и
  пересборку графа; «Live» показан на момент снимка, только для чтения.
- **Защита снимка.** Файлы из данных копируются только простыми именами, только обычными
  файлами внутри своего каталога (не символические ссылки), PNG — с сигнатурой. Пути
  корня данных и домашнего каталога вычищаются из ответов, итоговый снимок проверяется
  на них и при находке не записывается. Статика — белым списком. Снимок собирается рядом
  и подменяет прежний переименованием; прежний узнаётся по содержимому метки, каталог с
  посторонними файлами не перезаписывается. В странице снимка изменяющие запросы
  бросают ошибку. Справка команды и её вывод предупреждают: снимок публикует всё, что
  видно в вебморде.
- **Числа из отчётов — в разметку только числом** (`num()`/`recNum()`), в том числе в
  `data-css`: строка с разметкой на месте числа в `coverage.json` больше не попадает в
  innerHTML.
- **CSP сервера без `'unsafe-inline'` в `style-src`.** Стили в собираемой разметке —
  `data-css="…"`, ставятся через CSSOM (`static/api.js`); inline-стилей в разметке больше
  нет. Пути к статике в `index.html` — относительные (`static/…`); у сервера они
  разрешаются как прежде.

### partest-atlas 0.2.0 и partest 2.6.0

- **`partest>=2.6.0,<3` (был `>=1.8`).** До 2.6.0 `import partest` — а сервер импортирует
  `partest.redact`, и с ним пакет целиком — читал `confpartest` с `sys.path` и загружал
  спецификации из `swagger_files`, в том числе по URL. `python -m veha serve` из корня
  набора тестов проекта ходил бы в сеть при импорте, мимо красной линии «ноль
  исходящего трафика». С 2.6.0 импорт ничего не читает; держит
  `tests/test_import_egress.py` (на исходнике 2.5.0 он падает).
- **`partest-atlas>=0.1.0,<0.3`.** Формат артефактов 0.2 не менял (схема 2); поменялось,
  когда и какие записи пишутся. Пол не поднят: сервер не использует ничего, чего нет в 0.1.
- **Ребро «эндпоинт пишет в таблицу» из позадачного `db.effects` подписано окном:**
  «снято в окне теста, с фикстурами: insert». С 0.2 агент действительно пишет записи
  `scope: "test"`, и их окно — подготовка, вызов и уборка; эффект фикстуры модуля или
  сессии приписан тесту, на котором она сработала. Эндпоинты теста берутся из тела теста
  в Allure, поэтому ребро может принадлежать фикстуре; отделить её по записи нельзя.
  В панели таблицы то же сказано над списком «Что задели тесты».
- **Сессионные записи больше не называются «прогоном».** Агент копит прогоны в одном
  файле без метки прогона и схлопывает совпадающие записи — сумма сессионных записей
  таблицы не число за прогон. Узел таблицы: `runTouched` → `sessionTouched` с числом
  записей (`records`); панель — «Прогоны задели таблицу» с этой оговоркой. Узел топика:
  `runEvents` → `fileEvents` и `fileRecords`.
- **Сессионные записи `bus.flow` не идут в счёт «в тишине записей».** `afterWrite` у
  агента значит «часы HTTP видели пишущую запись», у сессионного среза он почти всегда
  `true` у прогона, который писал, а под pytest-xdist всегда `false` при нулевых `http`.
  Счётчик тишины топика (`runSilent` → `silentTests`) считается только по позадачным
  записям и не появляется, если их нет; панель топика говорит, что из сессионного
  замера не видно, кто писал — API или консьюмер.
- **Рёбра `reads` и `publishes` из позадачных окон** подписаны тем же окном, что и
  `writes`. Привязка требования «по таблице» подписана «по окну теста с фикстурами» —
  она строится из тех же записей.
- **Счётчик тишины топика считает разные тесты, а не записи** (один тест даёт по записи
  на прогон); подпись панели — «Тестов с событием в тишине».
- **Битая запись `db.effects` / `bus.flow` больше не роняет `/api/graph`.** Счётчик не
  числом, `nodeid` не строкой, нет таблицы или топика — запись отбрасывается и считается
  потерей `malformed` (`collected.lostRecords`). Числа записей в панели таблицы
  выводятся только числом.
- **История прогонов:** срез с `endpoints: 0` показан фишкой «не посчитано», а не «0%».
- **Тренд покрытия пропускает срезы с `endpoints: 0`** — отчёт, который ничего не
  посчитал, а не 0 %. С partest 2.6.0 молча пустые отчёты получают числа; без отсечения
  тренд нарисовал бы на этой границе рост с нуля.

### Формат partest: `meta.selection.optin` (partest 2.5.0)

- **Читается новый аддитивный ключ отчёта покрытия `meta.selection.optin`** — как partest
  решил каждый opt-in-набор маркеров: снят (`off`, сколько тестов), включён выражением
  `-m` (`markexpr`) или переменной окружения (`env`). Отчёты без ключа (partest до 2.5.0,
  проект без наборов) читаются как раньше; отсутствие ключа не считается «ничего не
  снято». Пол зависимости `partest>=1.8,<3` не поднят: ключ пишет partest проекта, а
  сервер читает JSON и кода partest для этого не вызывает.
- Шапка сцены и вывод при старте называют состояние словами: «opt-in: slow — снят
  (14 тестов)», «включён через -m», «включён через RUN_SLOW». Подсказка частичного
  прогона больше не выводит вложенные объекты выбора как `[object Object]`.
- `runner.history`: срез покрытия прогона хранит запись ключом `coverage.optin`, если
  она была в `coverage.json` (у полного и у частичного прогона; у частичного она больше
  не дублируется внутри `coverage.selection`).
- Тренд среднего покрытия разложен на серии по состоянию opt-in-наборов
  (`/api/runner/suites` → `trendSeries`; точки `trend` помечены `series`). Правило
  сравнимости — как у `partest.reports.compare`; прогоны без записи — отдельная серия.
- Демонстрационный набор: в `coverage.json` набор `slow` снят, в истории добавлен ночной
  полный прогон с `RUN_SLOW`.
