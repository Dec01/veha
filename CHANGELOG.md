# Изменения «Вехи»

Журнал изменений поведения сервера, новые версии сверху.

Версии — [Semantic Versioning](https://semver.org/), как у остальных пакетов семейства, с
поправкой на то, что Веха ещё в линии `0.x`: пока она не кончилась, ломающее изменение
поднимает **минорную** цифру, а не мажорную, и записывается здесь отдельным разделом
«Сломано».

| Изменение | Повышение в `0.x` | После `1.0` |
|---|---|---|
| исправление, документация, внутренняя переделка | патч | патч |
| новая команда, ключ, раздел `atlas.yaml`; новое поведение выключено по умолчанию | минор | минор |
| публичное (список ниже) меняет смысл или исчезает | минор + запись в «Сломано» | **мажор** |
| поднят пол `partest-atlas` или `partest` | минор | минор, мажор если сменилось то, что мы из них берём |
| формат артефактов агента | только вместе с владельцем формата (`partest-atlas`) | то же |

**Публичное:** команды `veha serve`, `veha demo`, `veha export-static` и их ключи; порт по
умолчанию 8770; переменные `ATLAS_SYSTEM` и `ATLAS_ENV`; раскладка каталога данных
(`atlas.yaml`, `atlas/<система>/<контур>/`, `coverage.json`, `allure-results/`) и разделы
`atlas.yaml`, которые читает сервер (`project`, `artifacts_dir`, `containers`, `domains`,
`screens`, `app_map`, `depends`, `tests`, `live`, `runner`, `logs`); то, что сервер пишет у
пользователя, — история прогонов `runner.history` и отметки `live/mr_checks.json`.

**Внутреннее** — меняется в любой версии без записи в «Сломано»: импорт `veha.*` (кроме
`veha.__version__`), HTTP-интерфейс `/api/*` вебморды, раскладка статического снимка.

## 0.2.2 — 2026-10-25

### Изменено

- **Тренд покрытия делится по правилу среднего.** partest 2.7.0 выносит строки
  `exception` (health-пробы и подобные) из среднего и пишет правило в `meta.avgRule: 2`;
  отчёт без ключа посчитан по прежнему правилу 1, где такая строка шла как 100 %. На
  прогоне с такими строками среднее после обновления partest опускается, хотя тесты те
  же. Срез покрытия в `runner.history` теперь хранит правило (`avgRule`) и число строк
  `exception` — при любом установленном `partest-atlas`: если агент их не записал, сервер
  берёт их из `coverage.json`. Тренд в окне раннера раскладывается на серии и по правилу,
  как по opt-in-наборам: правила 1 и 2 в одну линию не сводятся. Прогон без строк
  `exception` по обоим правилам даёт одно число, и такой переход серию не делит.
- **Тренд разделится в момент обновления veha**, если `partest-atlas` ниже 0.2.1 — даже
  когда partest не обновлялся: в записях прежних прогонов правила нет, они становятся
  серией «правило среднего не записано», а новые прогоны начинают свою. Точки такой серии
  показываются значениями через запятую с пометкой «не тренд»: они могли быть посчитаны по
  разным правилам (partest обновили раньше veha — 75, 75, 50, 50 — это не падение). Если
  серии расходятся по правилу, над трендом — строка: «Правило среднего сменилось (exception
  в среднем или вне его) — прежние прогоны отдельной серией» или, если в прежних записях
  правила нет, «В записях прежних прогонов правило среднего не записано — они отдельной
  серией»; пока у текущей серии одна точка — с хвостом «тренд — со следующего полного
  прогона». Единственная точка новой серии трендом не называется. Срез без строк
  `exception` относится к правилу текущей серии, так что проект на partest 2.6, у которого
  такая строка появилась, и откат 2.7 → 2.6 серию не делят.
- **В таблице «История прогонов»** у среднего, посчитанного не по правилу текущей серии,
  — чип с правилом («правило 1», «правило не записано»); `avg: null` при непустом отчёте —
  «не измерено: только exception».
- **Среднее группы в вебморде — по правилу отчёта.** «Покрытие → Эндпоинты» с группировкой
  и блоки доменов на карте по слоям при `meta.avgRule: 2` считают среднее без строк
  `exception`, как partest — `avgCoverage` своих групп; группа из одних `exception` —
  «покрытие не измерено». Отчёт без ключа считается, как раньше.
- **У частичного прогона в срезе истории нет долей глубины** (`depth.statusPct`,
  `depth.schemaPct`, partest 2.7.0) — как нет и среднего: они посчитаны по части набора.

### Исправлено

- **Пропущенная или упавшая запись прогона в историю больше не теряется молча.** Окно
  раннера одной строкой говорит, что последний прогон в историю не записан и почему, и
  что файл истории не прочитан, если это так. Битый `runs.json` (не JSON, схема новее)
  сервер проверяет сам и не трогает при любом `partest-atlas` — «пропущено»; файл, который
  разбирается, но с `runs` не списком записей, `partest-atlas` 0.2.1 не трогает
  («пропущено»), а 0.2.0 отказывается дописать с ошибкой («ошибка»), — файл цел в обоих
  случаях. У ошибки ввода-вывода в причине — только имя файла, без пути. Раньше исключение
  при записи проглатывалось, и вместе с ним пропускался сброс графа: сцена до перезапуска
  сервера показывала состояние до прогона.
- **`runner.history_limit` — только целое ≥ 1.** Ноль и отрицательное число `partest-atlas`
  понял бы как «стереть историю», дробь или строка роняли запись. Теперь берётся предел по
  умолчанию (10), а окно раннера об этом говорит.
- **Сервис без среднего** (`avgCoverage: null` у partest 2.7.0 — сервис из одних строк
  `exception`) в «Система → Сервисы» подписан «не измерено», а не пустой полосой.
  Сводка справа при `summary.avg: null` и непустом отчёте говорит «только exception», а не
  «отчёт пуст».
- **`coverage.json` с `meta` или `meta.selection` не объектом** больше не роняет снятие
  среза покрытия после прогона и сборку графа: такие ключи читаются как «нет»; правило
  среднего такого отчёта — «не записано» и на сервере, и в вебморде.

### Документация

- «Область не выбрана» описана так, как работает: не читаются только артефакты агента из
  `atlas/`, а `coverage.json`, Allure, `atlas.yaml` и `app_map` показываются; под шапкой —
  значок, причина — в подсказке и в выводе при старте.

### Демонстрация

- `coverage.json` набора — в форме partest 2.7.0 (`meta.avgRule`, `summary.exception`,
  `scored`, `depth`, глубина у строк); срезы истории снимает код сервера. Цифры сцены не
  изменились: строк `exception` в наборе нет. Генератору нужен `partest-atlas` не ниже 0.2.1.

## 0.2.1 — 2026-10-25

### Исправлено

- **Новая страница снимка `veha export-static` больше не встречается со старыми скриптами
  из кеша.** Страница грузила стили и скрипты по адресам без версии. Если хостинг кеширует
  JS и CSS снимка надолго, новая страница встречалась со старыми скриптами из кеша
  браузера, и демо не открывалось до принудительного обновления (Ctrl+F5). Теперь адрес
  каждого файла статики несёт версию по содержимому — `static/api.js?v=<первые 10 знаков
  SHA-256>` от тех байтов, что лежат в снимке: изменённый файл получает новый адрес,
  неизменный — прежний, два экспорта одного дерева по-прежнему дают побайтно одинаковый
  снимок. `veha serve` отдаёт страницу тем же кодом и с теми же адресами; кеш статики у
  сервера, как и раньше, выключен. Саму страницу снимка и `api/*.json` хостинг не должен
  кешировать надолго — это настройка сайта.

## 0.2.0 — 2026-10-19

### Изменено

- **Вебморда в языке сайта partest.ru.** Светлая и тёмная тема по настройке системы,
  системные шрифты, один зелёный акцент; свечение, градиенты и двенадцать декоративных
  цветов ушли. Цвет несёт только состояние эндпоинта: покрыт, частично, без тестов, нет в
  `coverage.json` (вызывался тестами или только объявлен в карте), упал.
- **Вид по умолчанию — карта по слоям** (2D): экраны → API по доменам → шина и сервисы →
  хранилища. Эндпоинт — квадрат с цветом покрытия и красной рамкой, если упал в прогоне;
  переключатель «Покрытие / Тесты» больше не нужен. Подписи — у списков, у цепочки
  выбранного узла и при наведении.
- **Связи — по выбору узла.** На открытии их нет; у выбранного узла видна его цепочка,
  остальное гаснет. Происхождение связи — начертанием: сплошная — снято на прогоне, штрих —
  объявлено, точки — выведено (приписано по окну теста, событие «в тишине записей», логи).
  Путь целиком — кнопкой в карточке. Таблица или топик без замера подписаны «замера записи нет»
  или «замера на прогоне нет», а не «тесты не задели».
- **Навигация — пять разделов в шапке** (Карта, Покрытие, Система, Требования, Прогон)
  вместо дока на двенадцать вкладок, рейла на четыре панели и полосы фильтров. Вкладки
  дока стали подразделами-страницами; строка таблицы ведёт на карту.
- **Карточка узла — одна колонка** разделов вместо пяти закладок; без выбора на её месте —
  сводка системы.
- **«Объём»** — прежняя изометрическая сцена вторым видом, в той же палитре, без свечения;
  связи и подписи — по тем же правилам, что у карты по слоям.
- **`tier` у `domains` и `containers`** в `atlas.yaml` по-прежнему читается, но поднимает
  палубу только в «Объёме»: на карте по слоям ярусов нет.
- **Идущий прогон** отмечается точкой под квадратом эндпоинта, а не цветом; число у раздела
  «Прогон» идёт за прогоном.

### Удалено

- Вид «Кольцо», ползунок плотности связей, флажок автовращения, кнопки «В лоб» и «Сброс»
  (поворот «Объёма» перетаскиванием остался).
- Переключатель «Покрытие / Тесты»: покрытие и прогон видны одновременно.
- Кнопка «Цепочка» и полоса фильтров над сценой: цепочка видна по выбору узла, состояния
  покрытия и прогона — пилюлями над картой. Фильтров «p95 больше 100 мс», «ходит во внешнюю
  систему» и «только связанные с чем-нибудь» больше нет; эндпоинты, объявленные, но не
  вызванные за прогон, — в «Требования → Контракт».
- Док внизу — его высота, сворачивание и кнопка «снять выделение»; повторный клик по строке
  больше не снимает выделение, строка ведёт на карту.
- Выведенные связи (общие пробелы, общий тест) на карте: они остались в «Система → Связи»,
  где набор выбирается рядом с таблицей.

## 0.1.0 — 2026-10-19

Первый выпуск, alpha. Веха — сервер карты тестирования: сводит артефакты агента
[`partest-atlas`](https://github.com/Dec01/partest-atlas), отчёт покрытия partest
(`coverage.json`) и результаты Allure в один граф и показывает его в браузере.

### Команды

- **`veha demo [--port N] [--no-browser]`** — карта на вымышленном наборе, который
  поставляется в пакете: `pip install veha && veha demo`. Только просмотр: прогоны не
  запускаются, на диск ничего не пишется; переменные области `ATLAS_SYSTEM`/`ATLAS_ENV`
  на демонстрацию не действуют.
- **Занятый порт** у `demo` и `serve` выясняется до того, как напечатан адрес: сообщение
  и код 2, браузер на чужой процесс не открывается. Браузер открывается, только когда
  сервер поднялся.
- **`veha serve --root <каталог>`** — вебморда над каталогом проекта: `atlas.yaml`,
  артефакты агента в `atlas/<система>/<контур>/`, `coverage.json`, `allure-results/`.
  Ключи `--port` (8770), `--no-browser`, `--system`/`--env` (иначе `ATLAS_SYSTEM`/
  `ATLAS_ENV`, как у агента), `--allow-run`. При старте печатается, что прочитано, а что
  нет и почему.
- **`veha export-static --root <каталог> --out <каталог>`** — статический снимок
  вебморды для сайта: страница, статика и ответы API JSON-файлами, без сервера; действия,
  которым нужен сервер, выключены с подписью «в демо недоступно». Снимок публикует всё,
  что видно в вебморде, — команда предупреждает об этом при каждом запуске.

### Карта

- **Сцена** «экран → эндпоинт → шина → хранилище»: экраны фронта, площадки API по
  доменам из `atlas.yaml`, топики, таблицы. Цвет — покрытие по методике partest или
  результат последнего прогона. Цепочка от элемента экрана до таблицы, поиск, палитра
  команд, два вида сцены.
- **Вкладки:** «Обзор» (покрытие, падения, чего не хватает чаще всего), «Методика»
  (эндпоинт × тип проверки), «Требования» (привязка к узлам карты и способ привязки),
  «Контракт» (объявлено в OpenAPI, но не вызывалось; коды ответов вне контракта),
  «Связи» (по происхождению: ручная карта, снятое на прогоне, логи контейнеров),
  «Схема БД», «Прогон» (длительности, дерево шагов и вложения упавших тестов), «Live»
  (состояние контейнеров и очередь merge request'ов из снимков, без опроса стенда).
- **Выводы подписаны.** Связь «эндпоинт — таблица» подписана окном теста, в котором
  снята; «топик — таблица» — выводом из тишины записей; требование — тем, как связано с
  тестом (прямой ссылкой, по эндпоинту, по таблице).
- **Каждый артефакт получает состояние** — `ok`, `missing`, `broken`, `newer`,
  `invalid`; данные берутся только из `ok`. Состояния — в `GET /api/artifacts`, в выводе
  при старте и в шапке сцены. Записи агента, не давшие ни одной связи, считаются по
  причинам и показываются.
- **Область** (система, контур): заданная явно → единственная на диске →
  `default/default` среди нескольких → иначе «не выбрана», с объяснением в шапке.
- **Отчёт без среднего** (`summary.avg: null` — отчёт, который ничего не посчитал)
  показан «—», а не 0 %; в тренд такой срез не идёт.
- **Частичный прогон и opt-in-наборы partest** (`meta.selection.optin`) названы словами;
  тренд среднего покрытия — только по полным прогонам и разложен на серии по составу.

### Прогоны из вебморды (только с `--allow-run`)

- Запуск наборов pytest из `runner.suites` (аргументы — только из конфигурации, не из
  запроса), перезапуск одного кейса, очистка `allure-results`, отметки проверки merge
  request'ов. Ход и итог прогона — из вывода pytest, в том числе под pytest-xdist и
  pytest-rerunfailures.
- Остановка прогона и выход сервера убивают всё дерево процессов прогона.
- История прогонов (`runner.history`) со срезом покрытия, состоянием стенда и
  привязкой к merge request'у.

### Защита

- Сервер слушает только `127.0.0.1`, отвечает только на `Host` `127.0.0.1:<порт>` и
  `localhost:<порт>`, изменяющие запросы принимает только со своей страницы; CSP без
  внешних источников и без inline-скриптов и стилей.
- Секреты (авторизация, пароли, токены, куки, закрытые ключи, JWT, токены сервисов,
  учётные данные в URL) маскируются во всём, что уходит в интерфейс. Маскирование —
  эвристика.
- Ноль исходящего трафика: ни телеметрии, ни CDN, ни внешних шрифтов; интерактивная
  документация FastAPI выключена.

### Совместимость

- Python ≥ 3.10.
- `partest-atlas>=0.1.0,<0.3` (схема артефактов 2), `partest>=2.6.0,<3`,
  `fastapi>=0.132.0,<1`, `uvicorn>=0.27,<1`, `pydantic>=2.7,<3`, `PyYAML>=6.0.2,<7`.
- Ставится в отдельное окружение (`pipx install veha` или свой venv), а не в окружение
  проекта с тестами.

### Известные ограничения

- Аутентификации нет — поэтому только loopback.
- Подключение своего проекта — ручная настройка `atlas.yaml`.
- Адаптеров для «Live» нет: вкладка читает снимки, которые кладёт не сервер.
- Единое поле `evidence` на каждой связи — план; сейчас происхождение подписано
  текстом.

Подробно — [docs/wiki/status.md](https://github.com/Dec01/veha/blob/v0.2.2/docs/wiki/status.md).
